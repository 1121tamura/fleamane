## F-01 販促コメント自動返信Bot

### 概要
いいねが付いた商品に対してセール価格を自動計算し、販促コメントを自動投稿する。

### 対象プラットフォーム
- ヤフオク（公式APIでいいね監視）
- メルカリ（Chrome拡張で監視）※後続対応

### 動作条件
- PC起動中のみ稼働（24時間クラウド不要）
- notificationサービス・pricingサービスが有効であること

### 処理フロー
```
いいね検知（ポーリング）
    ↓
対象商品IDで原価スプレッドシートを参照
    ↓
セール価格計算（現在販売価格 × 割引率）
    ↓
販促コメントテンプレートに価格を埋め込み
    ↓
コメント投稿
```

### セール価格計算ロジック
- **計算式**：現在の販売価格 × 割引率（%）
- **割引率**：DBに保存・管理画面から変更可能
- **原価割れチェック**：計算後価格が原価を下回る場合は投稿しない

### 未確定事項
- コメントテンプレートの管理方法
- ポーリング間隔
- メルカリのいいね検知方法

## F-04 一括値下げ

### 概要
GUIで指定した金額で出品中の全商品を一括値下げする。

### 対象プラットフォーム
- ヤフオク/ヤフフリ（Chrome拡張で操作）
- メルカリ（後続対応）

### 動作フロー
```
UI上で値下げ金額を入力（例：10円）
「値下げ実行」ボタン押下
    ↓ REST API
yahooauctionサービス
    ↓ localhost REST API
Chrome拡張
    ↓
ヤフオクページで全商品を順次値下げ
    ↓ WebSocket
進捗リアルタイム表示
完了通知
```

### 仕様
- 値下げ金額：GUIから動的に指定（固定10円ではない）
- 原価割れ防止：DB上の原価を参照し下限チェック
- 除外商品：設定画面で特定商品を除外可能（TODO）

## F-07 反応低調商品レポート

### 概要
毎朝、反応が悪い商品を自動判定してLINEで報告する。

### 動作条件
- PC起動中のみ稼働
- notificationサービス・mercariサービス・yahooauctionサービスが有効であること

### 判定ロジック（暫定）
以下の条件を組み合わせて判定：

| 判定種別 | 条件 | 推奨アクション |
|---------|------|--------------|
| 底値経過 | 底値設定から2日以上経過 | 再出品検討 |
| 値下げ推奨 | いいね数・価格・経過日数の閾値（要定義） | 値下げ |
| 再出品推奨 | 上記閾値かつ底値到達済み | 再出品 |

### 出力フォーマット（LINE）
```
【毎朝レポート】2024/01/15

📦 値下げ推奨 3件
・商品名A ¥3,000 出品14日 いいね2
  https://jp.mercari.com/item/xxx

♻️ 再出品推奨 1件
・商品名B ¥1,500 出品21日 いいね0
  https://jp.mercari.com/item/yyy
```

### 未確定事項
- 判定閾値の具体的な数値（いいね数・日数・価格）
- 「底値」の定義（原価ベース？設定した下限価格？）
- 配信時刻

## F-08 メルカリデータ取得・CSV出力

### 概要
Chrome拡張を通じてメルカリの出品・売上データを取得しSQLiteに保存する。日付範囲で絞り込み可能。

### 取得データ項目

| 項目 | 用途 |
|------|------|
| 取引ID | 重複排除・DB管理 |
| 商品名 | 基本情報 |
| 出品日 | 絞り込み条件 |
| 売上日（取引完了日） | 絞り込み条件・会計 |
| 販売価格 | 会計 |
| メルカリ手数料 | 会計・経費 |
| 送料 | 会計・経費 |
| 送料負担（出品者/購入者） | 会計 |
| 実収入 | 会計 |
| 商品URL | レポート |
| 商品画像URL | UI表示 |
| カテゴリ | 分析 |
| 発送方法 | 経費管理 |
| ステータス | 状態管理 |

### 商品ステータス

```
出品中 → 購入済み → 発送待ち → 発送済み → 取引完了
                                            ↓
                                        キャンセル
```

### 差分取得ロジック

```
【初回】
日付範囲指定で全件取得 → SQLite保存

【2回目以降（差分取得）】
パターンA：ステータス変化した商品
  例）出品中 → 取引完了 に変わった商品

パターンB：新規出品された商品
  前回取得時に存在しなかった出品中商品
```

### 動作フロー

```
【React UI】
日付範囲入力（開始日〜終了日）
「取得開始」ボタン押下
    ↓ REST API
【mercariサービス Go :8001】
ジョブID発行・DB保存（status: pending）
Chrome拡張にリクエスト送信
    ↓ localhost REST API
【Chrome拡張】
メルカリページ確認
  └── 未開 →「メルカリページを開いてください」をUIに表示・処理停止
  └── 開済 → データ取得処理へ
ページネーション自動処理（1ページ取得→1〜3秒待機→次ページ）
取得データをmercariサービスに送信
    ↓ WebSocket
【React UI】
進捗リアルタイム表示・完了後テーブル表示
```

### UI状態

| 状態 | 表示 |
|------|------|
| 待機中 | 「取得開始を押してください」 |
| 取得中 | プログレスバー＋件数＋推定残り時間＋中断ボタン |
| 完了 | 「○件取得完了」＋結果テーブル |
| エラー | エラー内容＋再試行ボタン |
| 中断 | 「○件取得済みで中断しました」＋再開ボタン |

### 大量データ対応
- 初回は最大2万件以上を想定
- 日付範囲を絞って分割取得を推奨（UI上でガイド表示）
- バックグラウンド実行（取得中もUI操作可能）
- 中断・再開機能あり

## F-09 会計データ出力（弥生CSV）

### 概要
メルカリ・ヤフオクの売上データを弥生会計のCSV形式に変換して出力する。

### 担当サービス
accountingサービス（:8006）

### 仕様
- 出力タイミング：UIボタンで任意のタイミング
- 保存先：config.yamlで指定したディレクトリ
- 対象：取引完了ステータスのデータのみ
- 対応フォーマット：弥生（将来：freee等追加可能）
- データソース：メルカリサービス・ヤフオクサービスのDBデータを統合

### 将来拡張
config.yamlの`format`を変更するだけで他会計ソフト対応可能な設計にする。
